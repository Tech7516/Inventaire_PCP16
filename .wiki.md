# Project Summary
Application web de gestion d’inventaire collaborative qui pilote des sessions de contrôle (lots/sous-lots) configurées en admin, historisées en PostgreSQL, et synchronisées entre mobile et desktop via un journal d’événements et des préférences centralisées côté cloud.

# Project Module Description
- Admin lots/sous-lots (config) : création/édition côté backend ; le front consomme ces configurations pour bâtir les sessions.
- Sessions & collaboration : création des sessions à partir des configurations ; navigation vers les sous-ensembles à contrôler.
- Checks des sous-entités : enregistrement des contrôles associés à chaque session, incluant le type d’intervention (DPS vs Désinfection).
- Inventaire (items) : persistance/affichage des items dérivés des configurations et des contrôles.
- Journal & événements : historisation des actions de session ; affichage via l’interface, avec traçage du type d’intervention.
- Rapports de divergences : calcul des écarts et génération de rapports à partir du journal.
- Édition de rapports (frontend) : ouverture d’un mode édition depuis le journal, modification des quantités réelles, puis sauvegarde en base.
- API backend & données : FastAPI + SQLAlchemy async + PostgreSQL, migrations via Alembic ; routes partagées pour contourner le filtrage RLS sur les données communes.
- Frontend : React/TypeScript ; synchronisation via endpoints backend partagés (journal/rapports/préférences/configs) pour garantir la cohérence inter-appareils.

# Directory Tree
app/
- backend/ : API FastAPI (routers, services, modèles/schemas, migrations)
- backend/alembic/versions/ : historique des migrations
- backend/data_models/ : modèles JSON (configs, items, logs, sessions, checks, rapports, préférences)
- backend/models/ : modèles SQLAlchemy (persistance des entités métier)
- backend/routers/ : endpoints CRUD et consultation par entité
- backend/routers/shared_data.py : API “shared” sans filtrage RLS (logs, rapports, préférences, configs lot)
- backend/services/ : logique métier (configs, opérations sessions/items/logs/checks/rapports, préférences)
- frontend/ : application React/TypeScript
- uploads/ : fichiers téléversés (stockage local)
- scripts/ : scripts de démarrage/packaging

# File Description Inventory
- app/frontend/src/pages/Inventory.tsx : page d’inventaire pour lots/sous-lots directs (CAI, V) ; gère la saisie DPS et le type d’intervention (Désinfection) avec validation/propagation.
- app/frontend/src/pages/Index.tsx : page d’entrée ; charge données/paramètres depuis le cloud.
- app/frontend/src/pages/SubEntities.tsx : page des sous-entités ; rend le contrôle “Désinfection” toujours cliquable et ajoute le bouton “Inventaire” en haut avec règles de validation.
- app/frontend/src/pages/Log.tsx : page journal ; affiche les variantes et lance l’édition de rapport via des liens `mode=edit`.
- app/frontend/src/pages/Report.tsx : page rapport ; ajoute un mode édition via `?mode=edit`, permet de modifier les quantités réelles et de sauvegarder.
- app/frontend/src/lib/inventory-api.ts : client API ; utilise endpoints collaboratifs et API partagée (logs/rapports/préférences).
- app/frontend/src/lib/useCloudPreferences.ts : hook de gestion des préférences via l’API partagée, basé désormais sur un cache singleton mutualisé.
- app/frontend/src/lib/preferenceCache.ts : cache singleton des préférences cloud avec déduplication du chargement, migration depuis localStorage, fallback, backoff en cas de 429, et dé-bounce des écritures.
- app/backend/alembic/versions/f16046e9fa2d_auto_update.py : migration liée aux préférences cloud.
- app/backend/data_models/app_preferences.json : modèle/référence JSON des préférences applicatives.
- app/backend/models/app_preferences.py : modèle SQLAlchemy de la table des préférences.
- app/backend/routers/app_preferences.py : endpoints CRUD préférences.
- app/backend/services/app_preferences.py : logique métier d’accès aux préférences.
- app/backend/routers/shared_data.py : routes partagées /api/v1/shared pour données communes (notamment logs/rapports/préférences/configs).

# Technology Stack
- Backend : FastAPI, PostgreSQL, SQLAlchemy (async), Alembic
- Frontend : React, TypeScript, Tailwind CSS
- Déploiement : Atoms Cloud

# Usage
1. Backend : `pip install -r app/backend/requirements.txt`
2. Frontend : `pnpm install` dans `app/frontend/`
3. Build frontend : `pnpm run build` dans `app/frontend/`
