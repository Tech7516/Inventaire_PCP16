# Project Summary

Application web collaborative de gestion d’inventaire destinée aux équipes opérationnelles. Les administrateurs configurent les lots, sous-lots et kits, tandis que les équipes réalisent sur mobile ou desktop des sessions historisées de vérification, d’inventaire et de désinfection.

Les données sont synchronisées avec PostgreSQL et alimentent les rapports de suivi. Les sessions actives verrouillent désormais le lot ou la variante sélectionnée pour éviter le démarrage simultané d’inventaires incompatibles. Ce verrouillage est partagé via le cloud et libéré automatiquement après abandon ou complétion.

# Project Module Description

- **Administration des lots et sous-lots** : configuration des lots utilisés pour générer les sessions.
- **Gestion des kits** : création et modification des kits personnalisables depuis la page Admin.
- **Kits prédéfinis** :
  - **SNV** : garrots, pansements, compresses, gants et accessoires associés.
  - **Accident Exposition Risque Viral (AERV)** : gants, compresses, Dakin, dispositifs de rinçage et fiche protocole.
  - **Mater/Accouchement** : matériel obstétrical, compresses, protections, sondes et accessoires néonataux.
  - **Kit de risque biologique renforcé** : kit dédié du Lot A.
- **Menus déroulants des kits** : affichage de la composition et des quantités directement dans l’inventaire.
- **Kits personnalisables** : gestion manuelle des kits Membre arraché, Biologique et Pharmacie.
- **Persistance des configurations** : chargement et sauvegarde cloud des définitions personnalisées et préférences d’instances.
- **Sessions collaboratives** : création, reprise, navigation et suivi des ensembles à contrôler.
- **Verrouillage des inventaires** :
  - le Lot A est verrouillé au niveau de la session active ;
  - les variantes du Lot C sont verrouillées pendant la session correspondante ;
  - les variantes d’inventaire direct du Lot V sont verrouillées jusqu’à complétion ou abandon ;
  - la variante utilisée est restaurée lors de la reprise d’une session ;
  - les sélecteurs incompatibles sont désactivés ;
  - un polling actualise les sessions actives pour libérer les verrouillages après une action d’un autre utilisateur.
- **Sous-sections multi-instances** :
  - ajout et suppression de cartes Lot B dans le Lot A ;
  - ajout et suppression de cartes DSA dans le VPS ;
  - sélection indépendante des variantes pour chaque instance.
- **Vérifications des sous-entités** : enregistrement des contrôles réalisés par sous-entité, instance et variante.
- **Validation des sessions** : sauvegarde désactivée tant que les instances Lot B et DSA requises ne sont pas complètes.
- **Désinfection des lots** : enregistrement des désinfections complètes dans le journal.
- **Inventaires DSA, T7 et AMS** : génération, persistance et affichage des éléments dédiés.
- **Variantes AMS** : AMS alpha, AMS Bravo, AMS Charlie et AMS Delta dans les lots A et C.
- **Journal et événements** : historisation des vérifications et désinfections, avec regroupement ordonné des lots.
- **Rapports de divergences** : calcul des écarts à partir des événements enregistrés.
- **API et données** : FastAPI, SQLAlchemy asynchrone, PostgreSQL et migrations Alembic.
- **Frontend** : interface React/TypeScript adaptée aux usages mobile et desktop.

# File Description Inventory

- `app/frontend/src/pages/Index.tsx` : charge les sessions actives, restaure les variantes utilisées, désactive les choix incompatibles et actualise périodiquement les verrouillages.
- `app/frontend/src/pages/Inventory.tsx` : gère les inventaires directs avec création, reprise, abandon et complétion de session, notamment pour le Lot V.
- `app/frontend/src/pages/SubEntities.tsx` : gère les sous-entités, variantes, instances Lot B et instances DSA VPS. Affiche le verrouillage de session et transmet la variante sélectionnée.
- `app/frontend/src/data/lots.ts` : définit les lots, variantes, inventaires, kits prédéfinis, articles et fonctions de résolution des définitions.
- `app/frontend/src/lib/configStore.ts` : charge et sauvegarde les configurations de kits et les préférences d’instances.
- `app/frontend/src/lib/inventory-api.ts` : gère les appels d’inventaire, les sessions, les abandons, les complétions et les rapports d’écart.
- `app/frontend/src/pages/Admin.tsx` : fournit l’interface d’administration pour créer, modifier et supprimer les articles des kits manuels.
- `app/frontend/src/pages/Log.tsx` : affiche et ordonne les événements de vérification et de désinfection.
- `app/frontend/src/components/ui/sonner.tsx` : configure les notifications de sauvegarde.
- `app/backend/routers/` : expose les routes de gestion, de session et de consultation des données.
- `app/backend/data_models/` : contient les schémas des configurations, inventaires, sessions, contrôles et rapports.
- `app/backend/models/` : définit les entités persistées en base.
- `app/backend/services/` : regroupe les traitements métier.
- `app/backend/alembic/versions/` : contient les migrations PostgreSQL.

# Technology Stack

- **Backend** : FastAPI, PostgreSQL, SQLAlchemy asynchrone, Alembic
- **Frontend** : React, TypeScript, Tailwind CSS
- **Composants UI** : shadcn/ui, Accordion
- **Notifications** : Sonner
- **Gestion des dépendances frontend** : pnpm
- **Validation** : lint et build frontend
- **Déploiement** : Atoms Cloud

# Usage

1. Installer les dépendances backend :

   ```bash
   pip install -r app/backend/requirements.txt
   ```

2. Installer les dépendances frontend :

   ```bash
   cd app/frontend
   pnpm install
   ```

3. Vérifier le lint frontend :

   ```bash
   pnpm run lint
   ```

4. Construire le frontend :

   ```bash
   pnpm run build
   ```

5. Démarrer les services selon la configuration de l’environnement de déploiement.

Le lint et le build frontend sont validés sans erreur.
