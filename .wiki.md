# Project Summary

Application web collaborative de gestion d’inventaire pour les équipes opérationnelles. Les administrateurs configurent les lots, sous-lots et kits, tandis que les équipes exécutent sur mobile ou desktop des sessions historisées de vérification, d’inventaire et de désinfection.

Les sessions peuvent être exécutées en parallèle sur des variantes différentes d’un même lot. Les doublons sur une même variante sont bloqués. Les kits prédéfinis sont désormais uniformisés dans l’administration et leurs inventaires associés sont correctement reliés.

# Project Module Description

- **Administration des lots et sous-lots** : configuration des lots utilisés pour générer les sessions.
- **Gestion des kits** : création et modification des kits personnalisables depuis la page Administration.
- **Kits éditables** : gestion uniforme de sept kits :
  - Kit SNV
  - Kit AERV
  - Kit Accouchement
  - Kit Membre arraché
  - Kit de risque biologique renforcé
  - Kit Biologique
  - Kit Pharmacie
- **Inventaires de kits** : les inventaires Accouchement, AERV et SNV utilisent leurs définitions de kits et leurs éventuelles configurations cloud.
- **Persistance des configurations** : sauvegarde cloud des définitions personnalisées et préférences d’instances.
- **Sessions collaboratives** : création, reprise, navigation et suivi des ensembles à contrôler.
- **Sessions multiples par variante** : plusieurs sessions actives sont autorisées pour un lot si les variantes diffèrent ; les doublons sur une même variante renvoient une erreur 409.
- **Verrouillage des variantes** : les variantes déjà utilisées sont grisées et indisponibles.
- **Sélection persistante** : la variante choisie est conservée entre les navigations.
- **Sous-sections multi-instances** : gestion des cartes Lot B dans le Lot A et des cartes DSA dans le VPS.
- **Vérifications des sous-entités** : enregistrement des contrôles par sous-entité, instance et variante.
- **Validation des sessions** : sauvegarde désactivée tant que les instances requises ne sont pas complètes.
- **Désinfection des lots** : enregistrement des désinfections dans le journal.
- **Inventaires DSA, T7 et AMS** : génération, persistance et affichage des éléments dédiés.
- **Journal et rapports** : historisation des événements et calcul des divergences.

# File Description Inventory

- `app/frontend/src/pages/Admin.tsx` : affiche et uniformise la section des kits personnalisés, incluant les sept kits éditables.
- `app/frontend/src/data/lots.ts` : définit les lots, variantes, inventaires, kits, articles et noms uniformisés des kits.
- `app/frontend/src/pages/Inventory.tsx` : utilise les définitions des kits Accouchement, AERV et SNV avec les overrides cloud pour leurs inventaires.
- `app/backend/routers/collaborative_inventory.py` : crée les sessions collaboratives et contrôle les conflits selon le lot et la variante.
- `app/frontend/src/pages/Index.tsx` : affiche les lots et sessions actives, persiste les variantes sélectionnées et verrouille les variantes utilisées.
- `app/frontend/src/pages/SubEntities.tsx` : lit les paramètres de variante et de session et rejoint la session correspondante.
- `app/frontend/src/lib/configStore.ts` : charge et sauvegarde les configurations de kits et préférences d’instances.
- `app/frontend/src/lib/inventory-api.ts` : gère les appels d’inventaire, sessions, complétions, abandons et rapports.
- `app/frontend/src/pages/Log.tsx` : affiche et ordonne les événements de vérification et de désinfection.
- `app/frontend/src/components/ui/sonner.tsx` : configure les notifications.
- `app/backend/routers/` : expose les routes de gestion, de session et de consultation.
- `app/backend/data_models/` : contient les schémas des configurations, inventaires, sessions et rapports.
- `app/backend/models/` : définit les entités persistées en base.
- `app/backend/services/` : regroupe les traitements métier.
- `app/backend/alembic/versions/` : contient les migrations PostgreSQL.

# Technology Stack

- **Backend** : FastAPI, PostgreSQL, SQLAlchemy asynchrone, Alembic
- **Frontend** : React, TypeScript, Tailwind CSS
- **Composants UI** : shadcn/ui, Accordion
- **Notifications** : Sonner
- **Gestion des dépendances frontend** : pnpm
- **Validation** : lint et build frontend

# Usage

1. Installer les dépendances backend :

   ```bash
   pip install -r app/backend/requirements.txt
   ```

2. Installer les dépendances frontend :

   ```bash
   cd app/frontend
   pnpm install
   ```

3. Vérifier la syntaxe du routeur backend :

   ```bash
   cd app/backend
   python -m py_compile routers/collaborative_inventory.py
   ```

4. Vérifier le lint frontend :

   ```bash
   cd app/frontend
   pnpm run lint
   ```

5. Construire le frontend :

   ```bash
   cd app/frontend
   pnpm run build
   ```

6. Démarrer les services selon la configuration de l’environnement de déploiement.
