# Project Summary
Application web de gestion d’inventaire collaborative : elle pilote des sessions de contrôle créées depuis une configuration admin (lots/sous-lots), historisées en base PostgreSQL, avec une interface mobile. Le produit vise des résultats de vérification identiques sur tous les appareils via centralisation cloud des préférences et journaux.

# Project Module Description
- Configuration lots/sous-lots (Admin) : création/édition côté backend, consommée par le front pour générer les sessions.
- Inventaire & collaboration : génération de sessions à partir des configurations et navigation vers les sous-ensembles à contrôler.
- Contrôles des sous-entités : enregistrement des checks associés à chaque session.
- Inventaire (items) : persistance et affichage des items dérivés des configurations et des contrôles.
- Log & événements : journalisation des actions et événements de session, consultation via l’interface.
- Rapports de divergences : calcul des divergences et génération de fichiers téléchargeables depuis le journal.
- Backend API & données : FastAPI + SQLAlchemy async + PostgreSQL, migrations via Alembic.
- Frontend : React/TypeScript, store et helpers côté front, notamment via un hook de préférences cloud.

# Directory Tree
app/
- backend/ : API FastAPI (routers, services, modèles/schemas, migrations)
- backend/alembic/versions/ : historique des migrations
- backend/data_models/ : fichiers JSON de modèles/références (config, items, logs, sessions, checks, rapports)
- backend/models/ : modèles SQLAlchemy pour la persistance (config, items, logs, sessions, checks, rapports)
- backend/routers/ : endpoints CRUD et consultation par entité
- backend/services/ : logique métier (chargement/sauvegarde configs, opérations sessions/items/logs/checks/rapports, préférences)
- frontend/ : application React/TypeScript
- frontend/src/lib/ : store et helpers côté front (client API + hook de préférences cloud)
- frontend/src/pages/ : pages (Index, Inventory, SubEntities, Admin, Log, etc.)
- uploads/ : stockage local de fichiers téléversés
- scripts/ : scripts de démarrage/packaging

# File Description Inventory
- app/frontend/src/pages/Inventory.tsx : page d’inventaire; utilise des préférences centralisées (cloud) pour conserver des choix UI cohérents.
- app/frontend/src/pages/Index.tsx : page d’entrée; charge les données et paramètres depuis le cloud pour éviter la divergence entre appareils.
- app/frontend/src/pages/SubEntities.tsx : page des sous-entités à contrôler; synchronise les préférences (lot-variants, dps-name, selected-variants) via le cloud.
- app/frontend/src/lib/inventory-api.ts : client API; expose désormais les appels nécessaires à la lecture/écriture des préférences cloud.
- app/frontend/src/lib/useCloudPreferences.ts : hook React pour gérer les préférences via DB cloud (load + set + remove + état de chargement).
- app/backend/alembic/versions/f16046e9fa2d_auto_update.py : migration Alembic ajoutant/ajustant le schéma nécessaire aux préférences cloud.
- app/backend/data_models/app_preferences.json : modèle/référence JSON des préférences applicatives.
- app/backend/models/app_preferences.py : modèle SQLAlchemy de la table app_preferences.
- app/backend/routers/app_preferences.py : endpoints backend pour CRUD des préférences.
- app/backend/services/app_preferences.py : logique métier d’accès aux préférences (lecture/écriture depuis PostgreSQL).

# Technology Stack
- Backend : FastAPI, PostgreSQL, SQLAlchemy (async), Alembic
- Frontend : React, TypeScript, Tailwind CSS
- Déploiement : Atoms Cloud

# Usage
1. Backend : `pip install -r app/backend/requirements.txt`
2. Frontend : `pnpm install` dans `app/frontend/`
3. Build frontend : `pnpm run build` dans `app/frontend/`
