# Project Summary

Application web collaborative de gestion d’inventaire pour les équipes opérationnelles. Les administrateurs configurent les lots, sous-lots et kits, tandis que les équipes réalisent sur mobile ou desktop des sessions historisées de vérification, d’inventaire et de désinfection.

Plusieurs sessions actives peuvent être exécutées en parallèle sur des variantes différentes d’un même lot. Les doublons sur une même variante restent bloqués. Lorsque toutes les variantes d’un lot sont déjà en cours de vérification, les contrôles de démarrage sont masqués et seuls les accès aux sessions existantes restent disponibles.

# Project Module Description

- **Administration des lots et sous-lots** : configuration des lots utilisés pour générer les sessions.
- **Gestion des kits** : création et modification des kits personnalisables.
- **Kits prédéfinis** : SNV, AERV, Mater/Accouchement et kit de risque biologique renforcé.
- **Kits personnalisables** : gestion manuelle des kits Membre arraché, Biologique et Pharmacie.
- **Menus déroulants des kits** : affichage des compositions et quantités dans l’inventaire.
- **Persistance des configurations** : sauvegarde cloud des définitions personnalisées et préférences d’instances.
- **Sessions collaboratives** : création, reprise, navigation et suivi des ensembles à contrôler.
- **Sessions multiples par variante** :
  - plusieurs sessions actives sont autorisées pour un même lot si les variantes diffèrent ;
  - une session active existante sur la même variante déclenche une erreur 409 explicite ;
  - les lots sans variante restent limités à une session active.
- **Navigation ciblée des sessions** : conservation de l’identifiant de session et de la variante lors des changements de page.
- **Verrouillage par variante** : les variantes associées à une session active sont grisées et indisponibles.
- **Sélection persistante** : la variante choisie n’est pas remplacée automatiquement par celle d’une autre session.
- **Disponibilité des contrôles** : lorsque toutes les variantes d’un lot sont actives, le sélecteur et le bouton de démarrage sont masqués ; un message d’information est affiché et les boutons de reprise restent disponibles.
- **Libellés des sessions** : affichage du lot, de la variante et du type de session lorsque ces informations sont disponibles.
- **Sous-sections multi-instances** : gestion des cartes Lot B dans le Lot A et des cartes DSA dans le VPS.
- **Vérifications des sous-entités** : enregistrement des contrôles par sous-entité, instance et variante.
- **Validation des sessions** : sauvegarde désactivée tant que les instances requises ne sont pas complètes.
- **Désinfection des lots** : enregistrement des désinfections dans le journal.
- **Inventaires DSA, T7 et AMS** : génération, persistance et affichage des éléments dédiés.
- **Journal et rapports** : historisation des événements et calcul des divergences.
- **API et données** : FastAPI, SQLAlchemy asynchrone, PostgreSQL et Alembic.
- **Frontend** : interface React/TypeScript adaptée aux usages mobile et desktop.

# File Description Inventory

- `app/frontend/src/pages/Index.tsx` : affiche les lots et sessions actives, verrouille les variantes utilisées et masque le sélecteur ainsi que le démarrage lorsque toutes les variantes sont occupées.
- `app/backend/routers/collaborative_inventory.py` : crée les sessions collaboratives et contrôle les conflits de sessions actives selon le lot et la variante.
- `app/frontend/src/pages/Inventory.tsx` : gère les inventaires directs, la reprise, l’abandon et la complétion des sessions.
- `app/frontend/src/pages/SubEntities.tsx` : lit les paramètres de variante et de session et rejoint uniquement la session correspondante.
- `app/frontend/src/data/lots.ts` : définit les lots, variantes, inventaires, kits et articles.
- `app/frontend/src/lib/configStore.ts` : charge et sauvegarde les configurations de kits et préférences d’instances.
- `app/frontend/src/lib/inventory-api.ts` : gère les appels d’inventaire, sessions, complétions, abandons et rapports.
- `app/frontend/src/pages/Admin.tsx` : permet de créer, modifier et supprimer les articles des kits manuels.
- `app/frontend/src/pages/Log.tsx` : affiche et ordonne les événements de vérification et de désinfection.
- `app/frontend/src/components/ui/sonner.tsx` : configure les notifications.
- `app/backend/routers/` : expose les routes de gestion, de session et de consultation.
- `app/backend/data_models/` : contient les schémas des configurations, inventaires, sessions et rapports.
- `app/backend/models/` : définit les entités persistées en base.
- `app/backend/services/` : regroupe les traitements métier.
- `app/backend/alembic/versions/` : contient les migrations PostgreSQL.

# Technology Stack

- **Backend** : FastAPI, PostgreSQL, SQLAlchemy asynchrone, Alembic
- **Frontend** : React, TypeScript, Tailwind CSS
- **Composants UI** : shadcn/ui, Accordion
- **Notifications** : Sonner
- **Gestion des dépendances frontend** : pnpm
- **Validation** : lint frontend et build frontend

# Usage

1. Installer les dépendances backend :

   ```bash
   pip install -r app/backend/requirements.txt
   ```

2. Installer les dépendances frontend :

   ```bash
   cd app/frontend
   pnpm install
   ```

3. Vérifier la syntaxe du routeur backend :

   ```bash
   cd app/backend
   python -m py_compile routers/collaborative_inventory.py
   ```

4. Vérifier le lint frontend :

   ```bash
   cd app/frontend
   pnpm run lint
   ```

5. Construire le frontend :

   ```bash
   pnpm run build
   ```

6. Démarrer les services selon la configuration de l’environnement de déploiement.
