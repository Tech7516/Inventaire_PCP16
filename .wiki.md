# Project Summary

Application collaborative de gestion d’inventaire des lots PCP16 pour les équipes opérationnelles. Les administrateurs configurent les lots, sous-lots et kits ; les équipes réalisent sur mobile ou desktop des vérifications, inventaires et désinfections historisés.

L’application combine une interface React/Vite et une API FastAPI avec une base relationnelle. Elle prend en charge les sessions collaboratives, les validations partielles, la persistance cloud des configurations et la consultation des journaux et rapports. Le dépôt conserve les emplacements `app/backend` et `app/frontend` pour rester compatible avec l’environnement Atoms, tout en préparant le build frontend sur Heroku.

# Project Module Description

- **Administration des lots et sous-lots** : configuration des lots qui servent à créer les sessions.
- **Gestion des kits** : création et modification des kits SNV, AERV, Accouchement, Membre arraché, Risque biologique renforcé, Biologique et Pharmacie.
- **Persistance des configurations** : sauvegarde et rechargement via l’API des quantités, suppressions et configurations de kits.
- **Inventaires** : génération et suivi des inventaires Accouchement, AERV, SNV, DSA, T7 et AMS.
- **Sessions collaboratives** : création, reprise, navigation et suivi des ensembles à contrôler.
- **Variantes de Lot C** : choix entre Alpha, Bravo, Auteuil et Neuilly ; les variantes partagent les sections sac de soin, sac d’O2 et DSA via des alias.
- **Gestion des variantes en session** : sessions multiples pour un lot si leurs variantes diffèrent ; les doublons sur une même variante renvoient une erreur 409. Les variantes utilisées sont grisées et la sélection est conservée entre les navigations.
- **Sous-sections multi-instances** : gestion des cartes Lot B dans les lots parents et des cartes DSA dans le VPS.
- **Anti-doublon DSA** : une variante DSA est désactivée de façon réciproque dans les sélecteurs Lot B, DSA standalone et VPS.
- **Validation partielle** : sauvegarde et export dès qu’un POM ou au moins un sous-ensemble est vérifié ; les contrôles sont enregistrés par sous-entité, instance et variante.
- **Désinfection** : enregistrement d’événements distincts pour les ensembles vérifiés. Le lot parent n’est journalisé que si ses propres sous-ensembles directs ont été vérifiés.
- **Journal et rapports** : historisation, regroupement et calcul des divergences. Le journal de désinfection affiche des cartes repliables, les dates, le compteur sur douze mois au format X/3 et l’historique complet ; chaque entrée peut être modifiée ou supprimée.
- **Build Heroku du frontend** : le `package.json` racine fournit les scripts `build` et `heroku-postbuild`, qui installent les dépendances dans `app/frontend` et lancent le build Vite.

- `app/frontend/src/pages/Log.tsx` : journal et rapports, avec regroupement des désinfections et historique dépliable.
- `app/frontend/src/pages/Index.tsx` : accueil, sessions actives et variantes persistées ou verrouillées.

- `app/backend/services/` : traitements métier.

# Technology Stack

- **Frontend** : React 18, TypeScript 5.5+, Vite 5, Tailwind CSS, React Router, TanStack React Query, Axios, Zod, React Hook Form, Recharts et Lucide.
- **Composants UI** : shadcn/ui, Radix UI et Accordion.
- **Notifications** : Sonner.
- **Backend** : Python 3.10+, FastAPI, Uvicorn, Pydantic 2, SQLAlchemy 2 asynchrone et Alembic.
- **Runtime de déploiement configuré** : Python 3.12.
- **Base recommandée** : PostgreSQL 12+ avec asyncpg.
- **Base de développement** : SQLite ; MySQL/MariaDB sont supportés par le code mais déconseillés en production.
- **Déploiement optionnel** : Heroku avec Procfile ; Mangum pour AWS Lambda.
- **Dépendances complémentaires** : python-jose, Stripe et OpenAI selon les fonctionnalités activées.
- **Gestionnaires de dépendances** : pip côté backend ; pnpm pour le développement frontend et npm pour le script de build Heroku.

# Usage

1. Installer les dépendances backend depuis la racine :

   ```bash
   pip install -r requirements.txt
   ```

   Ou directement depuis le backend :

   ```bash
   pip install -r app/backend/requirements.txt
   ```

2. Installer les dépendances frontend pour le développement :

   ```bash
   cd app/frontend
   pnpm install
   ```

3. Configurer au minimum `DATABASE_URL`, ainsi que `ENVIRONMENT` et `PORT` si nécessaire.

4. Vérifier la syntaxe backend :

   ```bash
   cd app/backend
   python -m py_compile routers/shared_data.py
   python -m py_compile routers/collaborative_inventory.py
   ```

5. Vérifier et construire le frontend :

   ```bash
   cd app/frontend
   pnpm run lint
   pnpm run build
   ```

   Le build Vite est généré dans `app/frontend/dist/`. Depuis la racine, le script `npm run build` exécute également `npm install` puis `npm run build` dans `app/frontend`.

6. Sur Heroku, `heroku-postbuild` installe les dépendances frontend avec npm et lance le build Vite après l’installation des dépendances Python. Configurer les variables d’environnement et la base de données avant le déploiement.

7. En production, provisionner PostgreSQL, appliquer les migrations, activer HTTPS, configurer le proxy inverse et vérifier le point de santé.

8. Pour AWS Lambda, activer le mode Lambda et utiliser un pool de connexions sans état via Mangum.

9. Après toute modification des configurations, variantes ou de la journalisation, exécuter le lint et le build frontend.
