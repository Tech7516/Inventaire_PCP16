# Project Summary

Application collaborative de gestion des inventaires des lots PCP16, destinée aux équipes opérationnelles. Les administrateurs configurent les lots, sous-lots et kits ; les équipes réalisent des vérifications, des inventaires et des désinfections sur mobile ou desktop, avec suivi des sessions et historique des opérations.

Le produit associe une interface React/Vite à une API FastAPI et une base relationnelle. Il prend en charge les sessions collaboratives, la validation partielle, la persistance des configurations et la consultation des journaux et rapports. Les journaux de vérification DSA, AMS et T7 conservent l’entrée la plus récente par variante, tandis que les désinfections restent cumulatives. Les entrées DSA/AMS/T7 suivent un ordre fixe dans les onglets Vérifications et Désinfection. En production, FastAPI peut servir le frontend compilé.

# Project Module Description

- **Administration des lots et sous-lots** : configuration des lots utilisés pour créer les sessions.
- **Gestion des kits** : création et modification des kits opérationnels.
- **Persistance des configurations** : sauvegarde et rechargement des quantités, suppressions et configurations de kits via l’API.
- **Inventaires et sessions collaboratives** : création et reprise des sessions, navigation et suivi des ensembles à contrôler.
- **Variantes et sous-sections** : prise en charge des variantes de lots et des cartes d’inventaire. Pour les DSA standalone, la variante sélectionnée est transmise à l’inventaire afin d’afficher les sections correspondantes, dont les accessoires T7 pour le Lot C.
- **Validation et désinfection** : sauvegarde partielle des contrôles et journalisation des ensembles vérifiés. Les vérifications DSA, AMS et T7 ne gardent que l’entrée la plus récente par variante ; les désinfections restent cumulatives.
- **Journal et rapports** : historique des opérations, calcul des divergences et consultation des désinfections. Dans les onglets Vérifications et Désinfection, les entrées DSA/AMS/T7 sont triées ainsi : T7 Alpha, T7 Bravo, DSA Alpha, DSA Bravo, DSA Charlie, DSA Delta, AMS Alpha, AMS Bravo, AMS Charlie, AMS Delta. Les entrées non reconnues apparaissent à la fin.
- **Affichage de la localisation** : « Passy » est réservé aux sous-lots du Lot A, à l’exception des DSA et AMS. Les autres lots ne l’affichent pas.
- **Build et déploiement frontend** : Vite compile l’application ; FastAPI peut servir le frontend compilé lorsque `app/frontend/dist/` existe.

# Technology Stack

- **Frontend** : React 18, TypeScript, Vite, Tailwind CSS, React Router, TanStack React Query, Axios, Zod, React Hook Form, Recharts et Lucide.
- **Composants UI** : shadcn/ui, Radix UI et Sonner.
- **Build frontend** : Vite, plugin React SWC, PostCSS et plugins Tailwind.
- **Backend** : Python 3.10+, FastAPI, Uvicorn, Pydantic 2, SQLAlchemy 2 asynchrone et Alembic.
- **Service des fichiers** : Starlette `StaticFiles` et `FileResponse`.
- **Base de données** : PostgreSQL avec asyncpg en production ; SQLite en développement.
- **Déploiement** : Heroku avec Uvicorn ; Mangum disponible pour AWS Lambda.
- **Gestionnaires de dépendances** : pip pour le backend ; pnpm pour le développement frontend et npm pour le build Heroku.

# Usage

1. Installer les dépendances backend depuis la racine :

   ```bash
   pip install -r requirements.txt
   ```

   Ou depuis le backend :

   ```bash
   pip install -r app/backend/requirements.txt
   ```

2. Installer les dépendances frontend :

   ```bash
   cd app/frontend
   pnpm install
   ```

   Avec npm :

   ```bash
   npm install
   ```

3. Configurer les variables d’environnement nécessaires, notamment `DATABASE_URL` et, selon le déploiement, `ENVIRONMENT` et `PORT`.

4. Démarrer l’API depuis `app/backend` :

   ```bash
   uvicorn main:app --reload
   ```

5. Vérifier la syntaxe backend depuis `app/backend` :

   ```bash
   python -m py_compile main.py
   python -m py_compile routers/shared_data.py
   python -m py_compile routers/collaborative_inventory.py
   ```

6. Vérifier et construire le frontend depuis `app/frontend` :

   ```bash
   pnpm run lint
   pnpm run build
   ```

   Le build est généré dans `app/frontend/dist/`. La construction npm est également disponible avec `npm run build`.

7. Pour Heroku, `heroku-postbuild` construit le frontend. Uvicorn sert l’API et le frontend compilé lorsqu’il existe.

8. Appliquer les migrations et provisionner PostgreSQL avant la mise en production.
