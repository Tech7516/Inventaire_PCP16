# Project Summary

Application web collaborative de gestion d’inventaire. Les administrateurs configurent les lots et sous-lots, tandis que les équipes réalisent sur mobile ou desktop des sessions historisées de vérification, d’inventaire et de désinfection.

Les événements sont synchronisés avec PostgreSQL et alimentent les rapports de suivi des lots et des inventaires DSA/AMS. Les DSA, T7 et AMS sont regroupés dans la catégorie « DSA et AMS » et affichent le nom de leur variante.

Les lots A et C prennent en charge une sous-section AMS avec quatre variantes : AMS alpha, AMS Bravo, AMS Charlie et AMS Delta. Chaque variante dispose de son inventaire dédié et ses événements sont historisés.

# Project Module Description

- **Administration des lots et sous-lots** : configuration des lots utilisés pour générer les sessions.
- **Sessions collaboratives** : création, navigation et suivi des ensembles à contrôler.
- **Vérifications des sous-entités** : enregistrement des contrôles réalisés par sous-entité et variante.
- **Désinfection des lots** : enregistrement des désinfections complètes dans le journal.
- **Inventaire DSA** : génération, persistance et affichage des éléments DSA.
- **Inventaire T7** : ajout conditionnel des accessoires requis pour les variantes `t7-alpha` et `t7-bravo`.
- **Inventaire AMS** : disponible dans les lots A et C avec les éléments et quantités configurés :
  - Sonde CH26 (5)
  - Sonde CH12 (3)
  - Stop vide, dont un prébranché (2)
  - Tubulure prébranchée (1)
  - Sac AMS (1)
- **Variantes AMS** : AMS alpha, AMS Bravo, AMS Charlie et AMS Delta.
- **Sélection des sous-entités** : sélection d’une variante et navigation vers l’inventaire correspondant.
- **Journal et événements** : historisation des vérifications et désinfections AMS avec le type de sac `ams`.
- **Ordre du journal** : dans les onglets Vérifications et Désinfection, les groupes sont affichés dans l’ordre suivant :
  1. Lot A
  2. Lot B
  3. Lot C
  4. VPS
  5. DSA et AMS
  6. Lot V
  7. Lot CAI
- **Affichage du journal AMS** : les entrées AMS affichent uniquement le nom de leur variante.
- **Rapports de divergences** : calcul des écarts à partir du journal, avec libellé AMS.
- **API et données** : FastAPI, SQLAlchemy asynchrone, PostgreSQL et migrations Alembic.
- **Frontend** : interface React/TypeScript adaptée aux usages mobile et desktop.

# File Description Inventory

- `app/frontend/src/data/lots.ts` : définit les configurations des lots A et C, les sous-entités AMS, leurs quatre variantes et les sections d’inventaire AMS.
- `app/frontend/src/pages/SubEntities.tsx` : affiche les sous-entités AMS, permet la sélection d’une variante, gère la navigation vers l’inventaire et enregistre les événements avec `sac_type: "ams"`.
- `app/frontend/src/pages/Inventory.tsx` : affiche le libellé AMS et gère l’inventaire sélectionné via le paramètre `sacType`.
- `app/frontend/src/pages/Log.tsx` : affiche et regroupe les événements du journal selon l’ordre Lot A, Lot B, Lot C, VPS, DSA et AMS, Lot V et Lot CAI dans les onglets Vérifications et Désinfection.
- `app/frontend/src/lib/inventory-api.ts` : ajoute le libellé AMS aux rapports de divergences.
- `app/frontend/src/components/ui/sonner.tsx` : configure l’affichage des confirmations de sauvegarde en haut à droite.
- `app/backend/routers/` : expose les routes de gestion, de consultation et de synchronisation des données.
- `app/backend/data_models/` : contient les schémas des configurations, inventaires, sessions, contrôles, journaux, rapports et préférences.
- `app/backend/models/` : définit les entités persistées en base de données.
- `app/backend/services/` : regroupe les traitements métier des sessions, inventaires, journaux, contrôles, rapports et préférences.
- `app/backend/alembic/versions/` : contient les migrations de structure PostgreSQL.

# Technology Stack

- **Backend** : FastAPI, PostgreSQL, SQLAlchemy asynchrone, Alembic
- **Frontend** : React, TypeScript, Tailwind CSS
- **Notifications** : Sonner
- **Gestion des dépendances frontend** : pnpm
- **Validation** : lint et build frontend
- **Déploiement** : Atoms Cloud

# Usage

1. Installer les dépendances backend :

   ```bash
   pip install -r app/backend/requirements.txt
   ```

2. Installer les dépendances frontend :

   ```bash
   cd app/frontend
   pnpm install
   ```

3. Vérifier le lint frontend :

   ```bash
   pnpm run lint
   ```

4. Construire le frontend :

   ```bash
   pnpm run build
   ```

5. Démarrer les services selon la configuration du projet et de l’environnement de déploiement.

Le lint et le build frontend sont validés.
