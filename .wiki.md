# Project Summary

Application collaborative de gestion d’inventaire des lots PCP16 pour les équipes opérationnelles. Les administrateurs configurent lots, sous-lots et kits ; les équipes réalisent sur mobile ou desktop des vérifications, inventaires et désinfections historisés.

L’application associe une interface React/Vite à une API FastAPI et une base relationnelle. Elle prend en charge les sessions collaboratives, la validation partielle, la persistance des configurations et la consultation des journaux et rapports. En déploiement Heroku, FastAPI peut servir le frontend compilé ; en l’absence du build, le comportement existant dans l’environnement Atoms est conservé.

# Project Module Description

- **Administration des lots et sous-lots** : configuration des lots utilisés pour créer les sessions.
- **Gestion des kits** : création et modification des kits SNV, AERV, Accouchement, Membre arraché, Risque biologique renforcé, Biologique et Pharmacie.
- **Persistance des configurations** : sauvegarde et rechargement des quantités, suppressions et configurations de kits via l’API.
- **Inventaires** : génération et suivi des inventaires Accouchement, AERV, SNV, DSA, T7 et AMS.
- **Sessions collaboratives** : création, reprise, navigation et suivi des ensembles à contrôler.
- **Variantes de Lot C** : choix entre Alpha, Bravo, Auteuil et Neuilly ; certaines sections sont partagées via des alias.
- **Gestion des variantes en session** : sessions multiples si leurs variantes diffèrent ; les doublons sur une variante identique renvoient une erreur 409.
- **Sous-sections multi-instances** : gestion des cartes Lot B dans les lots parents et des cartes DSA dans le VPS.
- **Anti-doublon DSA** : désactivation réciproque des variantes dans les sélecteurs Lot B, DSA standalone et VPS.
- **Validation partielle** : sauvegarde et export dès qu’un POM ou un sous-ensemble est vérifié ; contrôles enregistrés par sous-entité, instance et variante.
- **Désinfection** : journalisation distincte des ensembles vérifiés ; le lot parent est journalisé si ses propres sous-ensembles directs ont été vérifiés.
- **Journal et rapports** : historisation, regroupement et calcul des divergences, avec historique des désinfections modifiable et supprimable.
- **Service du frontend compilé** : si `app/frontend/dist/` existe au démarrage, FastAPI sert les assets Vite, la page d’accueil et le fallback React Router. Les routes API et de santé/documentation restent exclues du fallback. Sans ce répertoire, la route racine conserve sa réponse actuelle.

# Technology Stack

- **Frontend** : React 18, TypeScript 5.5+, Vite 5, Tailwind CSS, React Router, TanStack React Query, Axios, Zod, React Hook Form, Recharts et Lucide.
- **Composants UI** : shadcn/ui, Radix UI et Accordion ; notifications Sonner.
- **Backend** : Python 3.10+, FastAPI, Uvicorn, Pydantic 2, SQLAlchemy 2 asynchrone et Alembic.
- **Service des fichiers** : Starlette `StaticFiles` et `FileResponse`.
- **Base de données** : PostgreSQL avec asyncpg en production ; SQLite en développement.
- **Déploiement** : Heroku avec Uvicorn comme serveur web ; Mangum disponible pour AWS Lambda.
- **Dépendances optionnelles** : python-jose, Stripe et OpenAI selon les fonctionnalités activées.
- **Gestionnaires de dépendances** : pip pour le backend ; pnpm en développement frontend, npm pour le build Heroku.

# Usage

1. Installer les dépendances backend depuis la racine :

   ```bash
   pip install -r requirements.txt
   ```

   Ou depuis le backend :

   ```bash
   pip install -r app/backend/requirements.txt
   ```

2. Installer les dépendances frontend en développement :

   ```bash
   cd app/frontend
   pnpm install
   ```

3. Configurer les variables d’environnement nécessaires, notamment `DATABASE_URL` et, selon le déploiement, `ENVIRONMENT` et `PORT`.

4. Démarrer l’API depuis `app/backend` :

   ```bash
   uvicorn main:app --reload
   ```

5. Vérifier la syntaxe backend :

   ```bash
   cd app/backend
   python -m py_compile main.py
   python -m py_compile routers/shared_data.py
   python -m py_compile routers/collaborative_inventory.py
   ```

6. Vérifier et construire le frontend :

   ```bash
   cd app/frontend
   pnpm run lint
   pnpm run build
   ```

   Le build est généré dans `app/frontend/dist/`. Depuis la racine, `npm run build` exécute aussi l’installation et le build frontend.

7. Pour Heroku, `heroku-postbuild` construit le frontend. Uvicorn sert ensuite l’API et, si le répertoire `dist/` est présent, le frontend compilé. Configurer la base et les variables d’environnement avant le déploiement.

8. Appliquer les migrations et provisionner PostgreSQL avant la mise en production.
