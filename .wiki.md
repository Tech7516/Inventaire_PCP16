# Project Summary
Application web de gestion d’inventaire collaborative : elle pilote des sessions de contrôle (lots/sous-lots) configurées en admin, historisées dans PostgreSQL, et affichées via une interface mobile. Le produit vise une synchronisation identique sur tous les appareils grâce à un journal, des rapports et des préférences centralisés côté cloud.

# Project Module Description
- Configuration lots/sous-lots (Admin) : création/édition côté backend, consommée par le front pour générer les sessions.
- Inventaire & collaboration : génération de sessions à partir des configurations et navigation vers les sous-ensembles à contrôler.
- Contrôles des sous-entités : enregistrement des checks associés à chaque session.
- Inventaire (items) : persistance et affichage des items dérivés des configurations et des contrôles.
- Log & événements : journalisation des actions de session et consultation via l’interface.
- Rapports de divergences : calcul des divergences et génération de fichiers téléchargeables depuis le journal.
- Backend API & données : FastAPI + SQLAlchemy async + PostgreSQL, migrations via Alembic.
- Frontend : React/TypeScript ; préférences cloud et helpers, avec appels backend partagés pour garantir la cohérence inter-appareils.

# Directory Tree
app/
- backend/ : API FastAPI (routers, services, modèles/schemas, migrations)
- backend/alembic/versions/ : historique des migrations
- backend/data_models/ : modèles JSON de config/références (configurations, items, logs, sessions, checks, rapports)
- backend/models/ : modèles SQLAlchemy pour la persistance (config, items, logs, sessions, checks, rapports)
- backend/routers/ : endpoints CRUD et consultation par entité
- backend/routers/shared_data.py : API “shared” qui contourne le filtrage RLS pour logs, rapports, préférences et configs lots
- backend/services/ : logique métier (chargement/sauvegarde configs, opérations sessions/items/logs/checks/rapports, préférences)
- frontend/ : application React/TypeScript
- uploads/ : stockage local de fichiers téléversés
- scripts/ : scripts de démarrage/packaging

# File Description Inventory

- app/frontend/src/pages/Inventory.tsx : page d’inventaire ; s’appuie sur des préférences cohérentes via le cloud.
- app/frontend/src/pages/Index.tsx : page d’entrée ; charge données/paramètres depuis le cloud.
- app/frontend/src/pages/SubEntities.tsx : page des sous-entités ; synchronise variantes/DPS et choix via le cloud.
- app/frontend/src/lib/inventory-api.ts : client API ; utilise les endpoints collaboratifs et l’API partagée pour logs, rapports et préférences.
- app/frontend/src/lib/useCloudPreferences.ts : hook de gestion des préférences via l’API partagée (migration one-shot depuis localStorage).
- app/backend/alembic/versions/f16046e9fa2d_auto_update.py : migration ajoutant/ajustant le schéma des préférences cloud.
- app/backend/data_models/app_preferences.json : modèle/référence JSON des préférences applicatives.
- app/backend/models/app_preferences.py : modèle SQLAlchemy de la table des préférences.
- app/backend/routers/app_preferences.py : endpoints backend pour CRUD des préférences (route dédiée).
- app/backend/services/app_preferences.py : logique métier d’accès aux préférences.
- app/backend/routers/shared_data.py : routes partagées /api/v1/shared permettant un accès non filtré RLS aux données communes utilisées par les appareils.

# Technology Stack
- Backend : FastAPI, PostgreSQL, SQLAlchemy (async), Alembic
- Frontend : React, TypeScript, Tailwind CSS
- Déploiement : Atoms Cloud

# Usage
1. Backend : `pip install -r app/backend/requirements.txt`
2. Frontend : `pnpm install` dans `app/frontend/`
3. Build frontend : `pnpm run build` dans `app/frontend/`
