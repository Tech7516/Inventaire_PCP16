# Project Summary

Application web collaborative de gestion d’inventaire de lots PCP16 pour les équipes opérationnelles. Les administrateurs configurent les lots, sous-lots et kits, tandis que les équipes exécutent sur mobile ou desktop des sessions historisées de vérification, d’inventaire et de désinfection.

L’application associe une SPA React à une API FastAPI et une base relationnelle. Elle prend en charge les sessions parallèles sur différentes variantes d’un même lot, la persistance cloud des configurations et le suivi des opérations dans un journal.

# Project Module Description

- **Administration des lots et sous-lots** : configuration des lots utilisés pour générer les sessions.
- **Gestion des kits** : création et modification de sept kits personnalisables : SNV, AERV, Accouchement, Membre arraché, Risque biologique renforcé, Biologique et Pharmacie.
- **Inventaires de kits** : génération des inventaires Accouchement, AERV et SNV à partir des définitions et configurations cloud.
- **Sessions collaboratives** : création, reprise, navigation et suivi des ensembles à contrôler.
- **Sessions par variante** : plusieurs sessions actives sont possibles pour un lot si les variantes diffèrent ; un doublon sur la même variante renvoie une erreur 409.
- **Sélection persistante** : variantes déjà utilisées grisées et sélection conservée entre les navigations.
- **Sous-sections multi-instances** : gestion des cartes Lot B dans le Lot A et des cartes DSA dans le VPS.
- **Vérification des sous-entités** : contrôles enregistrés par sous-entité, instance et variante.
- **Validation** : sauvegarde désactivée tant que les instances requises ne sont pas complètes.
- **Désinfection** : enregistrement des opérations et gestion de leurs dates dans le journal.
- **Journal et rapports** : historisation, regroupement et calcul des divergences.
- **Journal de désinfection** : affichage condensé sur une ligne avec le lot ou la variante, le mois et l’année, ainsi que le compteur sur une fenêtre glissante de douze mois au format X/3. Les AMS et DSA/T7 sont affichés individuellement. Les actions de modification et de suppression restent disponibles par entrée.
- **Inventaires spécialisés** : prise en charge des inventaires DSA, T7 et AMS.
- **Hébergement** : frontend compilable en fichiers statiques et backend déployable sur serveur ASGI, conteneur, PaaS ou AWS Lambda.

# File Description Inventory

- `requirements.md` : référence pour l’hébergement, les runtimes, les dépendances, la base de données, les variables d’environnement et le déploiement.
- `app/frontend/src/pages/Admin.tsx` : administration et uniformisation des sept kits éditables.
- `app/frontend/src/data/lots.ts` : définition des lots, variantes, inventaires, kits, articles et libellés.
- `app/frontend/src/pages/Inventory.tsx` : affichage des inventaires et application des configurations cloud.
- `app/backend/routers/collaborative_inventory.py` : création des sessions et contrôle des conflits de variantes.
- `app/frontend/src/pages/Index.tsx` : affichage des lots, sessions actives, variantes persistées et verrouillées.
- `app/frontend/src/pages/SubEntities.tsx` : accès aux instances et sessions selon les paramètres de variante.
- `app/frontend/src/lib/configStore.ts` : chargement et sauvegarde des configurations de kits et préférences.
- `app/frontend/src/lib/inventory-api.ts` : appels liés aux inventaires, sessions, complétions, abandons et rapports.
- `app/frontend/src/pages/Log.tsx` : affichage du journal et des opérations de désinfection. L’onglet Désinfection utilise une présentation compacte, un compteur X/3 sur douze mois, et un regroupement individuel des AMS et DSA/T7 avec actions par ligne.
- `app/frontend/src/components/ui/sonner.tsx` : configuration des notifications.
- `app/backend/routers/` : routes de gestion, de session et de consultation.
- `app/backend/data_models/` : schémas des configurations, inventaires, sessions et rapports.
- `app/backend/models/` : entités persistées en base.
- `app/backend/services/` : traitements métier.
- `app/backend/alembic/versions/` : migrations de base de données.

# Technology Stack

- **Frontend** : React 18, TypeScript 5.5+, Vite 5, Tailwind CSS, React Router, TanStack React Query, Axios, Zod, React Hook Form, Recharts et Lucide.
- **Composants UI** : shadcn/ui, Radix UI et Accordion.
- **Notifications** : Sonner.
- **Backend** : Python 3.10+, FastAPI, Uvicorn, Pydantic 2, SQLAlchemy 2 asynchrone et Alembic.
- **Base de données recommandée** : PostgreSQL 12+ avec asyncpg.
- **Bases alternatives** : SQLite pour le développement ; MySQL/MariaDB supportés par le code mais non recommandés en production.
- **Déploiement optionnel** : Mangum pour AWS Lambda.
- **Dépendances complémentaires** : python-jose, Stripe et OpenAI selon les fonctionnalités activées.
- **Gestionnaires de dépendances** : pip côté backend et pnpm côté frontend.

# Usage

1. Installer les dépendances backend :

   ```bash
   pip install -r app/backend/requirements.txt
   ```

2. Installer les dépendances frontend :

   ```bash
   cd app/frontend
   pnpm install
   ```

3. Configurer au minimum `DATABASE_URL`, ainsi que `ENVIRONMENT` et `PORT` si nécessaire. PostgreSQL est recommandé en production.

4. Vérifier le routeur backend :

   ```bash
   cd app/backend
   python -m py_compile routers/collaborative_inventory.py
   ```

5. Vérifier le lint frontend :

   ```bash
   cd app/frontend
   pnpm run lint
   ```

6. Construire le frontend :

   ```bash
   cd app/frontend
   pnpm run build
   ```

   Le résultat est généré dans `dist/` et peut être servi par Nginx, Apache, Caddy ou un CDN avec fallback vers `index.html` pour les routes SPA.

7. Démarrer le backend avec un serveur ASGI selon la configuration de déploiement. Le port par défaut est 8000.

8. Pour la production, provisionner PostgreSQL, appliquer les migrations, activer HTTPS, configurer le proxy inverse et vérifier le endpoint de santé `GET /health`.

9. Pour AWS Lambda, activer le mode Lambda et utiliser le pool de connexions sans état via Mangum.

10. Après toute modification de `Log.tsx`, exécuter le lint et le build frontend pour valider la compilation et l’affichage du journal.
