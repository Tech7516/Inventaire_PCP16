# Project Summary

Application web collaborative de gestion d’inventaire. Les administrateurs configurent les lots et sous-lots, tandis que les équipes réalisent sur mobile ou desktop des sessions historisées de vérification, d’inventaire et de désinfection.

Les événements sont synchronisés avec PostgreSQL et alimentent les rapports de suivi des lots et des inventaires DSA/AMS. Les DSA et T7 sont regroupés dans la catégorie « DSA et AMS » et affichent uniquement le nom de leur variante, sans le contexte du lot parent.

Lorsqu’un T7 est sélectionné, l’inventaire conserve les éléments DSA et ajoute automatiquement une section « Accessoires T7 » avec les équipements requis. Les notifications de sauvegarde s’affichent désormais en haut à droite afin de ne pas masquer le bouton de sauvegarde situé en bas de page.

# Project Module Description

- **Administration des lots et sous-lots** : création et modification des configurations utilisées pour générer les sessions.
- **Sessions collaboratives** : création, navigation et suivi des ensembles à contrôler.
- **Vérifications des sous-entités** : enregistrement des contrôles réalisés par sous-entité.
- **Désinfection des lots** : enregistrement d’une entrée de journal pour chaque désinfection complète.
- **Inventaire DSA** : génération, persistance et affichage des éléments issus des configurations et contrôles.
- **Accessoires T7** : ajout conditionnel des équipements T7 à l’inventaire des variantes `t7-alpha` et `t7-bravo`.
- **Sélection DSA** : blocage des DSA uniquement lorsqu’ils appartiennent à un lot avec une session active.
- **Journal et événements** : historisation des actions pour l’audit et la traçabilité.
- **Catégorie DSA et AMS** : regroupement des DSA et T7 dans les onglets Vérifications et Désinfection.
- **Affichage des variantes** : affichage du seul nom de la variante DSA/T7.
- **Rapports de divergences** : calcul des écarts à partir du journal et production des rapports.
- **Édition des rapports** : modification des rapports depuis le journal puis sauvegarde en base.
- **Notifications utilisateur** : affichage des confirmations de sauvegarde dans une zone qui ne recouvre pas les actions principales.
- **API et données** : FastAPI, SQLAlchemy asynchrone, PostgreSQL et migrations Alembic.
- **Données partagées** : endpoints `/api/v1/shared` pour les journaux, rapports, préférences et configurations sans filtrage RLS.
- **Frontend** : interface React/TypeScript adaptée aux usages mobile et desktop.

# File Description Inventory

- `app/frontend/src/components/ui/sonner.tsx` : configure les notifications Sonner et leur affichage en haut à droite pour éviter le chevauchement avec les boutons en bas de page.
- `app/frontend/src/data/lots.ts` : définit les sections d’inventaire, dont la section « Accessoires T7 » avec les équipements et quantités suivants :
  - Glucomètre avec bandelette (1)
  - Thermomètre tympanique + embout (1)
  - Câble de sat (1)
  - Brassard tension (4)
  - Câble ECG (1)
- `app/frontend/src/pages/Inventory.tsx` : charge l’inventaire DSA, lit la variante sélectionnée et ajoute la section T7 uniquement pour `t7-alpha` et `t7-bravo`.
- `app/frontend/src/pages/SubEntities.tsx` : gère la sélection des DSA, les contrôles et la création des événements de vérification ou de désinfection. Transmet la variante DSA à la page d’inventaire pour permettre l’ajout conditionnel des accessoires T7.
- `app/frontend/src/pages/Log.tsx` : organise les entrées de vérification et de désinfection par catégorie, regroupe les DSA et T7 sous « DSA et AMS » et affiche uniquement le nom de la variante.
- `app/backend/routers/shared_data.py` : expose les données communes nécessaires à la synchronisation du frontend.
- `app/backend/data_models/` : contient les schémas JSON des configurations, inventaires, sessions, contrôles, journaux, rapports et préférences.
- `app/backend/models/` : définit les entités persistées en base de données.
- `app/backend/services/` : regroupe les traitements métier des sessions, inventaires, journaux, contrôles, rapports et préférences.
- `app/backend/alembic/versions/` : contient les migrations de structure PostgreSQL.

# Technology Stack

- **Backend** : FastAPI, PostgreSQL, SQLAlchemy asynchrone, Alembic
- **Frontend** : React, TypeScript, Tailwind CSS
- **Notifications** : Sonner
- **Gestion des dépendances frontend** : pnpm
- **Validation** : lint et build frontend
- **Déploiement** : Atoms Cloud

# Usage

1. Installer les dépendances backend :

   ```bash
   pip install -r app/backend/requirements.txt
   ```

2. Installer les dépendances frontend :

   ```bash
   cd app/frontend
   pnpm install
   ```

3. Vérifier le lint frontend :

   ```bash
   pnpm run lint
   ```

4. Construire le frontend :

   ```bash
   pnpm run build
   ```

5. Démarrer les services selon la configuration du projet et de l’environnement de déploiement.

Le lint et le build frontend sont validés après le repositionnement des notifications de sauvegarde.
