# Project Summary
Application web de gestion d’inventaire orientée collaboration : des sessions de contrôle par lot sont orchestrées entre utilisateurs, avec authentification et persistance PostgreSQL. Le produit permet de lancer un nouvel inventaire à partir de la configuration issue de l’admin (lots/sous-lots/sections), et propose des rapports de divergences ainsi qu’une consultation des logs, avec une UI optimisée mobile.

# Project Module Description
- Gestion de configuration lots/sous-lots (admin + persistance) : interface Admin pour créer/éditer, persistance côté backend, chargement côté front pour générer dynamiquement l’inventaire.
- Inventaire & collaboration : démarrage d’un nouvel inventaire depuis les configs chargées, génération des pages de sous-ensembles, coordination via sessions.
- Rapports de divergences : conservation et affichage des états par lot/variant avec indicateurs associés.
- Logs : regroupement, priorisation et catégorisation des événements.
- Gestion des erreurs : garde-fous UI et route catch-all pour éviter les écrans cassés.
- Backend API & données : FastAPI + SQLAlchemy async + PostgreSQL, migrations via Alembic.
- Frontend : React/TypeScript, chargement dynamique des configs via un store.

# Directory Tree
app/
- backend/ : API FastAPI (routers, services, modèles/schemas, handlers, migrations)
- backend/alembic/versions/ : historique des migrations
- backend/data_models/ : modèles de configuration (ex: lot_configs.json)
- backend/models/ : modèles de persistance des configurations
- backend/routers/ : endpoints de configuration lots/sous-lots
- backend/services/ : logique de chargement/sauvegarde des configurations
- frontend/ : application React/TypeScript
- frontend/src/lib/ : store de configuration côté front
- frontend/src/pages/ : pages (Index, Inventory, SubEntities, Admin, etc.)
- uploads/ : stockage local des fichiers téléversés
- scripts/ : scripts de démarrage/packaging

# File Description Inventory
- app/frontend/src/App.tsx : routage/composition de l’application (mise à jour liée au flux de configs)
- app/frontend/src/pages/Index.tsx : page d’accueil (chargement/initialisation de configuration via le store)
- app/frontend/src/pages/Inventory.tsx : affichage du nouvel inventaire basé sur les configs chargées
- app/frontend/src/pages/SubEntities.tsx : rendu des sous-ensembles basé sur les configs (suppression des valeurs statiques)
- app/frontend/src/pages/Admin.tsx : administration des configurations lots/sous-lots
- app/frontend/src/lib/configStore.ts : store client pour charger les configurations depuis la BDD
- app/backend/alembic/versions/e1745981cf1c_auto_update.py : migration de schéma liée aux configurations
- app/backend/data_models/lot_configs.json : modèle de configuration de référence/fallback
- app/backend/models/lot_configs.py : modèles backend pour lot configs
- app/backend/routers/lot_configs.py : routes API pour lire/écrire les configurations
- app/backend/services/lot_configs.py : services de chargement/persistance des configurations

# Technology Stack
- Backend : FastAPI, PostgreSQL, SQLAlchemy (async), Alembic, asyncpg
- Frontend : React, TypeScript, Tailwind CSS
- Déploiement : Atoms Cloud

# Usage
1. Backend : `pip install -r app/backend/requirements.txt`
2. Frontend : `pnpm install` dans `app/frontend/`
3. Build frontend : `pnpm run build` dans `app/frontend/`
