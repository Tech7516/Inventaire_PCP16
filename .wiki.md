# Project Summary
Application web de gestion d’inventaire orientée collaboration : des sessions de contrôle par lot sont orchestrées entre utilisateurs, avec authentification et persistance PostgreSQL. Le produit permet de lancer un nouvel inventaire en utilisant la configuration (lots/sous-lots/sections) issue de l’admin, et fournit des rapports de divergences ainsi qu’une consultation des logs, avec une UI optimisée mobile.

# Project Module Description
- **Gestion de configuration lots/sous-lots (BDD + admin)** : création/édition depuis l’interface Admin, persistance côté backend, et chargement côté front pour construire dynamiquement l’inventaire.
- **Inventaire & collaboration** : démarrage de nouveaux inventaires à partir des configurations chargées, génération de pages de sous-ensembles, coordination via sessions.
- **Rapports de divergences** : conservation et affichage des états lot/variant et indicateurs associés.
- **Logs** : regroupement/priorisation et catégorisation des événements.
- **Gestion des erreurs** : garde-fous UI et route catch-all pour éviter les écrans cassés.
- **Backend API & données** : FastAPI + SQLAlchemy async + PostgreSQL, migration via Alembic.
- **Frontend** : React/TypeScript, chargement dynamique des configs via un store.

# Directory Tree
app/
- **backend/** : API FastAPI (main, routers, services, modèles, schemas, handlers, migrations)
- **backend/alembic/versions/** : historiques de migrations (nouvelle version ajoutée)
- **backend/data_models/** : données de configuration (ex: lot_configs.json)
- **backend/models/** : modèles de persistance de la configuration
- **backend/routers/** : endpoints de configuration (lots/sous-lots)
- **backend/services/** : logique de chargement/sauvegarde des configurations
- **frontend/** : application React/TypeScript
- **frontend/src/lib/** : store de configuration côté front
- **frontend/src/pages/** : pages (Index, Inventory, SubEntities, Admin, etc.)
- **uploads/** : stockage local des fichiers téléversés
- **(scripts)** : scripts de démarrage/packaging

# File Description Inventory
- **app/frontend/src/App.tsx** : composition/routage de l’application (mise à jour liée au flux de configs)
- **app/frontend/src/pages/Index.tsx** : initialisation/chargement de configuration depuis le store (correction flux lot)
- **app/frontend/src/pages/Inventory.tsx** : affichage du nouvel inventaire basé sur les configs chargées dynamiquement
- **app/frontend/src/pages/SubEntities.tsx** : rendu des sous-ensembles basé sur les configs BDD (suppression du recours aux valeurs statiques)
- **app/frontend/src/pages/Admin.tsx** : page d’administration pour modifier les configurations de lots/sous-lots
- **app/frontend/src/lib/configStore.ts** : store client pour charger les configurations depuis la BDD
- **app/backend/alembic/versions/e1745981cf1c_auto_update.py** : migration de schéma liée aux configurations
- **app/backend/data_models/lot_configs.json** : modèle de configuration (source de référence/fallback)
- **app/backend/models/lot_configs.py** : modèle(s) backend pour lot configs
- **app/backend/routers/lot_configs.py** : routes API pour lire/écrire les configurations
- **app/backend/services/lot_configs.py** : services de chargement/persistance des configurations

# Technology Stack
- **Backend** : FastAPI, PostgreSQL, SQLAlchemy (async), Alembic, asyncpg
- **Frontend** : React, TypeScript, Tailwind CSS
- **Déploiement** : Atoms Cloud

# Usage
1. Backend : `pip install -r app/backend/requirements.txt`
2. Frontend : `pnpm install` dans `app/frontend/`
3. Build frontend : `pnpm run build` dans `app/frontend/`
