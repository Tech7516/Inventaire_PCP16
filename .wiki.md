# Project Summary
Application web collaborative de gestion d’inventaire. Les administrateurs configurent les lots et sous-lots, tandis que les équipes réalisent des sessions historisées de vérification ou de désinfection sur mobile et desktop. Les événements sont synchronisés via PostgreSQL et alimentent des rapports de suivi séparant les lots et les inventaires DSA/AMS.

# Project Module Description
- **Administration des lots et sous-lots** : création et modification des configurations utilisées pour générer les sessions.
- **Sessions collaboratives** : création, navigation et suivi des ensembles à contrôler.
- **Vérifications des sous-entités** : enregistrement d’une ligne par sous-entité contrôlée.
- **Désinfection des lots** : enregistrement d’une seule ligne de journal pour chaque désinfection complète d’un lot, sans duplication par sous-lot ou variante.
- **Inventaire** : génération, persistance et affichage des éléments issus des configurations et contrôles.
- **Journal et événements** : historisation des actions pour l’audit et la traçabilité.
- **Rapports de divergences** : calcul des écarts à partir du journal et production des rapports.
- **Édition des rapports** : modification des rapports depuis le journal puis sauvegarde en base.
- **API et données** : FastAPI, SQLAlchemy asynchrone, PostgreSQL et migrations Alembic.
- **Données partagées** : endpoints `/api/v1/shared` pour les journaux, rapports, préférences et configurations sans filtrage RLS.
- **Frontend** : interface React/TypeScript adaptée aux usages mobile et desktop.
- **DSA/AMS** : entrées regroupées dans le journal de vérification et de désinfection via une puce dédiée, sans onglet séparé.

# File Description Inventory
- `app/frontend/src/pages/SubEntities.tsx` : gère la saisie des contrôles et la création des événements de vérification ou de désinfection. Une désinfection complète produit désormais une seule entrée de journal par lot.
- `app/frontend/src/pages/Inventory.tsx` : gère les désinfections des lots directs et crée déjà une entrée unique par sauvegarde.
- `app/backend/routers/shared_data.py` : expose les données communes nécessaires à la synchronisation du frontend.
- `app/backend/data_models/` : contient les schémas JSON des configurations, inventaires, sessions, contrôles, journaux, rapports et préférences.
- `app/backend/models/` : définit les entités persistées en base de données.
- `app/backend/services/` : regroupe les traitements métier des sessions, inventaires, journaux, contrôles, rapports et préférences.
- `app/backend/alembic/versions/` : contient les migrations de structure PostgreSQL.

# Technology Stack
- **Backend** : FastAPI, PostgreSQL, SQLAlchemy asynchrone, Alembic
- **Frontend** : React, TypeScript, Tailwind CSS
- **Gestion des dépendances frontend** : pnpm
- **Déploiement** : Atoms Cloud

# Usage
1. Installer les dépendances backend :
   ```bash
   pip install -r app/backend/requirements.txt
   ```
2. Installer les dépendances frontend :
   ```bash
   cd app/frontend
   pnpm install
   ```
3. Vérifier le lint frontend :
   ```bash
   pnpm run lint
   ```
4. Construire le frontend :
   ```bash
   pnpm run build
   ```
5. Démarrer les services selon la configuration du projet et de l’environnement de déploiement.
