# Project Summary

Application web collaborative de gestion d’inventaire des lots PCP16 pour les équipes opérationnelles. Les administrateurs configurent les lots, sous-lots et kits, tandis que les équipes réalisent sur mobile ou desktop des sessions historisées de vérification, d’inventaire et de désinfection.

L’application associe une SPA React à une API FastAPI et une base relationnelle. Elle prend en charge les sessions parallèles par variante, les validations partielles, la persistance cloud des configurations, le suivi des opérations et la consultation de rapports.

# Project Module Description

- **Administration des lots et sous-lots** : configuration des lots utilisés pour générer les sessions.
- **Gestion des kits** : création et modification des kits SNV, AERV, Accouchement, Membre arraché, Risque biologique renforcé, Biologique et Pharmacie.
- **Inventaires** : génération et suivi des inventaires Accouchement, AERV, SNV, DSA, T7 et AMS à partir des configurations cloud.
- **Sessions collaboratives** : création, reprise, navigation et suivi des ensembles à contrôler.
- **Sessions par variante** : plusieurs sessions actives sont possibles pour un lot lorsque les variantes diffèrent ; un doublon sur une même variante renvoie une erreur 409.
- **Sélection persistante** : variantes utilisées grisées et sélection conservée entre les navigations.
- **Sous-sections multi-instances** : gestion des cartes Lot B dans le Lot A et des cartes DSA dans le VPS.
- **Anti-doublon DSA réciproque** : une même variante DSA est désactivée dans les sélecteurs Lot B, DSA standalone et VPS, quelle que soit sa source de sélection.
- **Validation partielle** : sauvegarde et export possibles dès qu’un POM ou au moins un sous-ensemble est vérifié, sans exiger la validation préalable de Lot B, DSA ou AMS.
- **Vérification des sous-entités** : contrôles enregistrés par sous-entité, instance et variante.
- **Désinfection** : chaque désinfection est enregistrée comme un événement distinct.
- **Journalisation des sous-ensembles** : les Lot B, DSA, AMS et autres sous-ensembles vérifiés sont enregistrés séparément lors de la désinfection d’un lot parent.
- **Journal et rapports** : historisation, regroupement et calcul des divergences.
- **Journal de désinfection** : cartes repliables regroupées par lot, variantes, dernière date, compteur sur douze mois au format X/3 et historique complet.
- **Actions d’historique** : modification de la date et suppression de chaque entrée de désinfection.

# File Description Inventory

- `requirements.md` : référence pour l’hébergement, les runtimes, les dépendances, la base de données, les variables d’environnement et le déploiement.
- `app/frontend/src/pages/Admin.tsx` : administration des lots et des kits éditables.
- `app/frontend/src/data/lots.ts` : définition des lots, variantes, inventaires, kits, articles et libellés.
- `app/frontend/src/pages/Inventory.tsx` : affichage des inventaires, application des configurations cloud et journalisation des désinfections.
- `app/frontend/src/pages/SubEntities.tsx` : gestion des instances et variantes, validation partielle et anti-doublon DSA réciproque entre les sélecteurs Lot B, standalone et VPS.
- `app/frontend/src/pages/Log.tsx` : journal et rapports, avec regroupement des désinfections, variantes spécialisées, compteur glissant X/3 et historique dépliable.
- `app/frontend/src/pages/Index.tsx` : affichage des lots, sessions actives, variantes persistées et verrouillées.
- `app/frontend/src/lib/configStore.ts` : chargement et sauvegarde des configurations de kits et préférences.
- `app/frontend/src/lib/inventory-api.ts` : appels liés aux inventaires, sessions, complétions, abandons, journaux et rapports.
- `app/backend/routers/shared_data.py` : création et mise à jour des journaux ; les désinfections sont insérées comme nouvelles entrées et les vérifications restent idempotentes.
- `app/backend/routers/collaborative_inventory.py` : création des sessions et contrôle des conflits de variantes.
- `app/frontend/src/components/ui/sonner.tsx` : configuration des notifications.
- `app/backend/routers/` : routes de gestion, de session et de consultation.
- `app/backend/data_models/` : schémas des configurations, inventaires, sessions et rapports.
- `app/backend/models/` : entités persistées en base.
- `app/backend/services/` : traitements métier.
- `app/backend/alembic/versions/` : migrations de base de données.

# Technology Stack

- **Frontend** : React 18, TypeScript 5.5+, Vite 5, Tailwind CSS, React Router, TanStack React Query, Axios, Zod, React Hook Form, Recharts et Lucide.
- **Composants UI** : shadcn/ui, Radix UI et Accordion.
- **Notifications** : Sonner.
- **Backend** : Python 3.10+, FastAPI, Uvicorn, Pydantic 2, SQLAlchemy 2 asynchrone et Alembic.
- **Base recommandée** : PostgreSQL 12+ avec asyncpg.
- **Base de développement** : SQLite ; MySQL/MariaDB supportés par le code mais déconseillés en production.
- **Déploiement optionnel** : Mangum pour AWS Lambda.
- **Dépendances complémentaires** : python-jose, Stripe et OpenAI selon les fonctionnalités activées.
- **Gestionnaires de dépendances** : pip côté backend et pnpm côté frontend.

# Usage

1. Installer les dépendances backend :

   ```bash
   pip install -r app/backend/requirements.txt
   ```

2. Installer les dépendances frontend :

   ```bash
   cd app/frontend
   pnpm install
   ```

3. Configurer au minimum `DATABASE_URL`, ainsi que `ENVIRONMENT` et `PORT` si nécessaire.

4. Vérifier la syntaxe backend :

   ```bash
   cd app/backend
   python -m py_compile routers/shared_data.py
   python -m py_compile routers/collaborative_inventory.py
   ```

5. Vérifier le lint frontend :

   ```bash
   cd app/frontend
   pnpm run lint
   ```

6. Construire le frontend :

   ```bash
   cd app/frontend
   pnpm run build
   ```

   Le résultat est généré dans `dist/` et peut être servi par un serveur web ou un CDN avec fallback vers `index.html`.

7. Démarrer le backend avec un serveur ASGI selon la configuration de déploiement.

8. En production, provisionner PostgreSQL, appliquer les migrations, activer HTTPS, configurer le proxy inverse et vérifier le endpoint de santé.

9. Pour AWS Lambda, activer le mode Lambda et utiliser un pool de connexions sans état via Mangum.

10. Après toute modification de la vérification ou de la journalisation des désinfections, exécuter le lint frontend, le build frontend et la vérification Python backend.
